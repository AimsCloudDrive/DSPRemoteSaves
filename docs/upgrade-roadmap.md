# DSP 云存档服务 v2 方案升级分析

> 基于 `docs/rust-rewrite-and-sm-crypto-plan-v2.md`（v2，约 1480 行）的评审。
> 结论：**功能与安全主线已经可以进入实施**；但有 6 个上线前必须补的缺口、8 个值得排进 v2.1 的升级，以及 3 个最容易被忽略但会真出事的点。
> 版本：2026-10-17

---

## 0. 总体判断

已经覆盖：国密信封、无状态模组、JWT + refresh、注册/找回、版本模型、配额、审计、双语、Redis、MinIO 备份、Docker/Caddy 部署。

还缺的不是“功能”，而是**生产化**：

| 维度 | 现状 | 差距 |
|---|---|---|
| 合规 | 公开注册 + 邮箱 + IP + 审计 | 没有隐私政策、数据导出、账号注销、PII 保留策略 |
| 管理端安全 | 内网/VPN + 密码 + JWT | 没有 MFA、没有会话列表/单设备下线 |
| 上传可靠性 | 固定 30 分钟会话、init 查配额 | 慢速 2GB 会超时；并发 init 会超卖（已在本轮补进 v2） |
| 灾备 | 每日备份到同机 MinIO | 同机不是异地；没有自动恢复演练 |
| 邮件 | 企业邮 SMTP | 没有退信/投诉处理、DMARC 未强制、新域名未预热 |
| 运维 | 日志/指标/健康检查 | 没有优雅停机、维护模式、告警通道、OTel |
| 审计 | Mongo 180 天 | 管理员可改/删，没有防篡改 |
| 存储成本 | 版本不限 + 1GB/人 | 无去重、无冷热分层；1000 人上限约 1TB |
| 接口治理 | 手写 API | 无 OpenAPI、无版本化、无生成客户端 |
| 供应链 | Cargo/npm | 无 cargo-deny/SBOM/镜像扫描 |

## 1. P0：上线前必须补

### 1.1 上传会话滑动 TTL + 配额预留（已补进 v2）

**问题**

- 固定 30 分钟会话：2GB 在 2 Mbps 上行需要约 2.2 小时，必然失败。
- `init` 只查 `usedBytes`：两个并发上传都能通过，`complete` 后一起超出 1GB。

**改法**

- 会话改为**空闲 10 分钟过期，每次 `chunk` 续期，最长 24 小时**。
- `users` 增加 `reservedBytes`；`init` 原子校验 `usedBytes + reservedBytes + size <= quota` 并预留；`complete` 转正式，失败/过期释放。
- 验收：两个并发 `init` 只能一个成功；4 小时慢速上传不中断。

> 这两条已经写进 v2 §5.6 / §5.7 / §4.5，属于“方案内已修”，但实现时必须有并发测试。

### 1.2 合规与隐私（公开注册的前置）

**为什么**

公开注册 + 邮箱验证 + IP + 审计日志 = 处理个人信息。没有隐私政策/注销/导出，甲方验收、应用商店、投诉任一处都会卡。

**做什么**

- 注册页勾选《用户协议》《隐私政策》；记录同意时间、版本。
- 数据导出：用户可导出个人资料、存档清单、版本记录、审计中与本人相关的记录（JSON/CSV）。
- 账号注销：软删 + 7 天冷静期 → 硬删/匿名化；Mongo、Redis、MinIO 备份到期自然淘汰。
- 保留期限写清楚：审计 180 天、应用日志 30 天、备份 30 天、验证码 5 分钟。
- 日志/审计中的邮箱/IP 掩码；Redis key 用哈希，不写明文邮箱。
- 与法务确认：ICP/公安备案、未成年人保护、是否涉及跨境。

**验收**

注销后 PII 不可查；导出覆盖用户全部数据；隐私政策版本可追溯。

### 1.3 管理端 MFA + 会话管理

**为什么**

admin 能删用户、下载全部存档、改配额。仅靠 VPN + 密码，一旦账号泄露就是全量数据。

**做什么**

- TOTP（6 位/30s）+ 10 个一次性恢复码；admin 强制开启，首次登录引导绑定。
- 会话列表：设备、IP、最后活跃、创建时间；支持单设备下线、全部下线。
- 下载/回退/删除/改配额/轮换密钥全部审计；大文件下载单独记一条。
- 可选：WebAuthn/passkey 作为下一步。

**验收**

未绑定 TOTP 不能进 `/admin`；踢下线 30s 内 access 失效（`tokenVersion++` + `jti` 黑名单）。

### 1.4 备份异地 + 自动恢复演练

**为什么**

同机 MinIO 与主数据同故障域；主机/磁盘坏了两份一起没。备份没恢复过 = 没有备份。

**做什么**

- 每日备份后 `mc mirror` 到另一台机器/云 OSS/S3；对象存储开版本/对象锁。
- 每周自动恢复到临时 MongoDB + 目录，校验用户数、版本数、随机 10 个文件 SM3；失败告警。
- 备份加密（age/AES-GCM），密钥独立于服务器保管。
- 记录 RPO/RTO：当前 RPO 24h、RTO 1h；如果业务要求更高，再上 oplog/PITR。

**验收**

恢复演练成功率 100%；从零恢复一次全流程计时 ≤1 小时。

### 1.5 邮件退信/投诉 + DMARC

**为什么**

验证码是注册主路径；退信率高会拖垮域名信誉，最后所有邮件进垃圾箱。

**做什么**

- 企业邮退信转发到 `bounce@domain`，用 IMAP 拉取/解析 DSN，标记无效邮箱；连续退信 3 次暂停该地址。
- 投诉/退订处理（事务邮件也建议）；DMARC 从 `p=none` → `p=quarantine` → `p=reject`。
- 新域名/新 IP 预热：首周每天几十封，逐步加量；监控进箱率。
- 发信失败告警到管理员（复用企业邮或 webhook）。

**验收**

退信率 <2%、投诉率 <0.1%；QQ/163/Gmail 各测 10 封进收件箱。

### 1.6 优雅停机 + 维护/只读模式

**为什么**

部署重启时正在合并的分片会变成半截文件；磁盘满/Mongo 故障时继续写会产生不一致。

**做什么**

- SIGTERM：停止接新上传 → 等待进行中的 `chunk/complete`（最长 30s）→ flush 审计 → 关闭。
- 维护模式：只读（可登录/下载，禁注册/上传/改密/删除），返回 503 + `Retry-After`；管理端开关。
- 磁盘 <10% 或 Mongo 不可用：自动只读，避免半写。
- 启动时 reconcile：清理孤儿 temp、修正 `reservedBytes`。

**验收**

滚动重启 10 次无半截文件；维护模式不丢请求、不产生 500。

### 1.7 供应链与依赖审计

**做什么**

- `cargo-deny`（advisory/license/bans/sources）+ `cargo-audit`；CI 阻断高危。
- `cargo-cyclonedx` 生成 SBOM，随 release 发布；镜像 Trivy 扫描。
- Docker 非 root、只读根文件系统、`cosign` 签名；前端 lockfile + `pnpm audit`。

**验收**

CI 无高危；release 附 SBOM；镜像无 root。

## 2. P1：上线后 1~3 个月

| 升级 | 为什么 | 怎么做 | 工作量 |
|---|---|---|---|
| **SM4 信封 v2（CBC/GCM）** | ECB 相同明文块可见；参考实现只是兼容要求 | `encVersion=2`：随机 IV + SM4-CBC/GCM；`smkey` 加密 `key‖iv`；v1 保留给模组 | 2~3d |
| **滑动窗口限流** | 固定窗口在边界会双倍突刺 | Redis ZSET：`ZREMRANGEBYSCORE` + `ZCARD` + `ZADD`，Lua 原子；或令牌桶 | 1~2d |
| **Refresh 轮换 + 重用检测** | 旧 refresh 被窃取可续命 7 天 | 每次刷新签发新 token，旧 token 标记 used；重用 → 吊销整个 session family + 告警 | 1~2d |
| **审计哈希链/WORM** | 管理员可改/删审计 | 每条 `hash = SM3(prevHash‖canonical(doc))`；每日 anchor 到 MinIO 对象锁；`acc-cli audit verify` | 2~3d |
| **OpenAPI + TS 客户端** | 手写接口易漂移 | `utoipa` 生成 spec + Scalar UI；`openapi-typescript` 生成 `web/src/api/generated.ts`；契约测试 | 2~3d |
| **OpenTelemetry + 告警** | 现在只有日志/指标 | OTLP → Tempo/Jaeger；Prometheus + Grafana；Alertmanager 发邮件/webhook | 2~3d |
| **内容寻址去重 + 冷热分层** | 版本不限 + 1GB/人，存储会膨胀 | 按 SM3 存 blob + refcount；相同内容只存一份；旧版本转 MinIO，本地留索引 | 5~7d |
| **静态加密 at rest** | 磁盘/备份被拿走即泄露 | 每文件 SM4-GCM，key 由 KMS/SM2 包裹；下载流式解密；备份含 wrapped key | 3~5d |
| **账号安全包** | 降低接管风险 | 登录通知、新设备提醒、HIBP k-anonymity 弱密码检查 | 2d |
| **边缘防护** | Caddy 不是 WAF | 云 WAF/CDN + 边缘限流 + Bot 管理；保留 Caddy 做 TLS | 1~2d |
| **Schema 版本/迁移** | 未来加字段不能靠手改 | `settings.schemaVersion` + `acc-cli migrate` 幂等脚本；启动校验版本 | 2d |

## 3. P2：规模化/未来

| 方向 | 触发条件 | 关键点 |
|---|---|---|
| 多实例 HA | 单机扛不住或不能停机 | Mongo 副本集 + Redis Sentinel + 共享对象存储 + KMS keyring；上传会话已在 Mongo，无需粘性会话 |
| TLCP / 密码机 | 要过密评 | HSM 托管 SM2 私钥、TLCP 网关、密钥管理制度；软件实现过不了 |
| WebAuthn/passkey | 管理端安全再加一层 | 比 TOTP 抗钓鱼；作为 admin 第二因子 |
| 存档元数据解析 | 产品差异化 | 解析 `.dsv` 头部（星区/游戏版本/时长），展示而非修改 |
| 分享/团队空间 | 用户需求 | 签名短期链接、权限、审计；注意隐私与滥用 |
| 计费/套餐 | 商业化 | 配额套餐、支付、发票；与当前 1GB 默认配额解耦 |
| 多地域/异地多活 | 跨区玩家 | 对象存储复制、Mongo 跨区、读写分离；成本高 |

## 4. 现有方案的 8 个技术薄弱点

1. **固定窗口限流**：`INCR+EXPIRE` 在窗口边界会放过 2× 限额；改滑动窗口。
2. **SM4-ECB**：密码短、密钥随机，风险可控，但不符合“最佳实践”；v2 上 CBC/GCM。
3. **审计可篡改**：Mongo 里的审计，root/管理员可改；加哈希链或外部 WORM。
4. **JWT 吊销的 30s 窗口**：`user:ver` 缓存 30s，DEL 失败时最坏 30s；可接受，但要写进 SLA。
5. **单机单点**：Mongo/Redis/MinIO/应用全在一台；当前量级可接受，但不能承诺 99.9%。
6. **无 API 版本化**：新接口建议 `/v1/admin/...`；老模组路径永久冻结。
7. **无 schema 迁移**：全新库不等于永远不改；先加 `schemaVersion`。
8. **无 graceful shutdown**：部署/重启会打断上传；见 P0。

## 5. 如果只做 5 件事

1. **配额预留 + 上传滑动 TTL**（已补进 v2，必须测并发）。
2. **管理端 MFA + 会话列表 + 下载审计**。
3. **异地备份 + 自动恢复演练**。
4. **隐私政策 + 数据导出 + 账号注销**。
5. **邮件退信/投诉处理 + DMARC 强制**。

这 5 件做完，方案从“能跑”变成“能对用户负责”。SM4 v2、审计哈希链、OpenAPI 可以排后。

---

## 6. 不建议现在做

- **多实例/HA**：当前单机 + 1GB/人，先把单机跑稳；HA 的复杂度（共享存储、keyring、Redis Sentinel）会拖慢上线。
- **自建邮件**：已分析，负收益。
- **微服务拆分**：一个二进制足够，拆了只会增加运维。
- **自研对象存储/存储引擎**：MinIO + 磁盘够用。
- **把 Redis 当事实源**：限流/缓存/锁可以，用户/配额/存档/审计不行。
- **把存档内容放 Redis**：太大，且 eviction 风险。
- **过早做分享/计费/WebAuthn**：等真实需求。
- **自定义加密协议**：坚持标准 SM2/SM4；v2 也只上标准 CBC/GCM，不发明模式。

## 7. 验收指标（建议写进上线 checklist）

| 维度 | 指标 |
|---|---|
| 安全 | 抓包/日志 0 明文密码；admin MFA 覆盖 100%；高危依赖 0 |
| 可靠 | 上传成功率 >99%；RPO ≤24h；RTO ≤1h；恢复演练 100% |
| 性能 | 登录 p95 <500ms；文件列表 p95 <200ms（Redis 命中 <50ms）；Redis p95 <5ms |
| 合规 | 隐私政策/同意/导出/注销可用；审计 180 天；日志 30 天 |
| 邮件 | 退信率 <2%；投诉率 <0.1%；QQ/163/Gmail 进箱测试通过 |
| 运维 | 滚动重启无半截文件；维护模式可用；告警 5 分钟内到达 |

### 一句话

**v2 的主线不用推翻；上线前补“合规、MFA、灾备、上传并发、邮件退信、优雅停机”六件事，上线后再做“SM4 v2、滑动限流、审计防篡改、OpenAPI、可观测性、去重分层”。**
